## File 1 — `src/db/db.ts`

```ts
import Dexie, { type Table } from 'dexie'

// ─── Row shapes ───────────────────────────────────────────────────
// These are plain row types for the IDB tables.
// Full domain types (Project, NodeRecord, EdgeRecord) live in src/entity/
// and will be imported here in Step 5 when the entity layer exists.
// For now we use minimal inline types so the schema compiles cleanly.

export interface ProjectRow {
  id:          string
  name:        string
  description: string
  createdAt:   number
  updatedAt:   number
}

export interface NodeRow {
  id:        string
  projectId: string
  type:      string
  label:     string
  position:  { x: number; y: number }
  size:      { w: number; h: number }
  data:      string   // JSON.stringify of the full typed node object
  createdAt: number
  updatedAt: number
}

export interface EdgeRow {
  id:         string
  projectId:  string
  fromNodeId: string
  toNodeId:   string
  type:       string
  label:      string
}

// ─── Database class ───────────────────────────────────────────────

class ArchflowDB extends Dexie {
  projects!: Table<ProjectRow, string>
  nodes!:    Table<NodeRow,    string>
  edges!:    Table<EdgeRow,    string>

  constructor() {
    super('archflow')

    this.version(1).stores({
      // Primary key first, then indexed fields
      // Non-indexed fields do not need to be listed
      projects: 'id, updatedAt',
      nodes:    'id, projectId, type, [projectId+type]',
      edges:    'id, projectId, fromNodeId, toNodeId',
    })
  }
}

// ─── Singleton instance ───────────────────────────────────────────
// Import `db` anywhere in the app to access IndexedDB.
// Never instantiate ArchflowDB directly outside this file.

export const db = new ArchflowDB()
```

## File 3 — `src/sw/sw.ts`

```ts
import { cleanupOutdatedCaches, precacheAndRoute } from 'workbox-precaching'
import { clientsClaim } from 'workbox-core'

declare let self: ServiceWorkerGlobalScope

// Take control of all clients immediately when a new SW activates
self.skipWaiting()
clientsClaim()

// Precache all assets generated by Vite (injected at build time by vite-plugin-pwa)
precacheAndRoute(self.__WB_MANIFEST)

// Remove caches left behind by older versions of this SW
cleanupOutdatedCaches()

// ─── Cross-tab sync channel ───────────────────────────────────────
// When any tab writes to IndexedDB it posts a message on this channel.
// All other open tabs receive the message and invalidate their
// TanStack Query cache so they re-fetch and stay in sync.
//
// The channel name is the single source of truth.
// It must match the name used in src/main.tsx exactly.
//
// Message shape:
//   { type: 'IDB_CHANGED', table: string, projectId: string | null }
//
// Nothing in the service worker acts on these messages — it only
// relays them. The tab-side listener in main.tsx handles invalidation.

self.addEventListener('message', (event: ExtendableMessageEvent) => {
  if (event.data && event.data.type === 'IDB_CHANGED') {
    // Broadcast to all other tabs (excluding the sender)
    self.clients.matchAll({ type: 'window' }).then((clients) => {
      clients.forEach((client) => {
        if (client.id !== event.source?.id) {
          client.postMessage(event.data)
        }
      })
    })
  }
})
```

// BroadcastChannel is used as the direct path (same origin, same browser).
// The SW relay above handles the case where BroadcastChannel is unavailable.
const bc = new BroadcastChannel(SYNC_CHANNEL)

bc.onmessage = (event: MessageEvent) => {
  if (event.data?.type === 'IDB_CHANGED') {
    // TODO Step 5: queryClient.invalidateQueries()

## Why each decision was made

**`db.ts` uses inline row types instead of importing from `@entity`**
The entity layer does not exist yet (that is Step 3 in the original build plan,
but we are building IDB first so pages can be tested). When Step 3 is complete,
`NodeRow.type` and `EdgeRow.type` will be tightened to use the real enums.
For now `string` is correct and avoids a circular dependency.

**`nodes.data` is `string` not `object`**
The full typed node object (MicroserviceNode, EntityNode, etc.) is stored as
`JSON.stringify(node)`. This keeps the Dexie schema simple and decouples
persistence from the TypeScript type system. The service layer in Step 5
will handle serialisation and deserialisation.

**`[projectId+type]` compound index**
Needed for queries like "give me all entity nodes in project X" without
scanning every node row. Dexie compound index syntax is `[field1+field2]`.

**SW uses `injectManifest` strategy not `generateSW`**
`injectManifest` lets us write the SW ourselves (`src/sw/sw.ts`) rather than
having Workbox auto-generate it. This is required because we need the custom
message relay logic for cross-tab sync. `generateSW` would overwrite that logic.

**`skipWaiting()` + `clientsClaim()`**
This is correct for a local-first app. There is no backend to go out of sync with.
A new SW should take over immediately.

**`BroadcastChannel` is the direct path for cross-tab**
`BroadcastChannel` works tab-to-tab within the same origin without going through
the SW. The SW relay in `sw.ts` is a fallback for browsers where BC is unavailable
or for tabs that were opened from a different context. Both paths produce the same
message shape so the listener in `main.tsx` handles both identically.
